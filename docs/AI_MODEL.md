## 1. What the AI does

VoxG's AI answers one question about a short piece of audio:

> **"Was this voice produced by a human vocal tract, or generated by a machine?"**

It is an **audio deepfake detector** built on a pretrained **wav2vec2** transformer
fine-tuned for speech spoofing detection (ASVspoof-style). Given a 2–4 second
waveform window it outputs:

- `is_synthetic` — boolean verdict (real human vs AI-generated), and
- `confidence` — the model's certainty in that verdict (0–1).

The demo plays a simulated phone call and classifies it in 3-second chunks while
you listen — so the "AI verdict" appears live, the way it would need to work on a
real scam call.

## 2. How it works (mechanics)

### 2.1 The model

**Checkpoint:** `Bisher/wav2vec2_ASV_deepfake_audio_detection`
(Hugging Face; selected after auditing 4 candidate checkpoints for a complete
config — the original plan's first choice was missing its feature-extractor
config on the Hub and would have silently loaded a random classification head).

```
raw waveform (16 kHz) → wav2vec2 feature extractor → 12-layer transformer
→ pooled representation → 2-way classification head → softmax
→ p_fake (synthetic) vs p_real (human)
```

- **wav2vec2** learns directly from raw audio samples (self-supervised
  pretraining on 960 h of speech), so it captures channel/vocoder artifacts that
  spectrogram-based detectors miss.
- The ASVspoof-fine-tuned head converts those representations into a
  real-vs-spoof decision. Its config declares `id2label = {0: fake, 1: real}`;
  the backend resolves the "synthetic" index at startup
  (`synthetic_index=0`) rather than hardcoding it.

### 2.2 The inference path (one chunk)

1. **Load** — `soundfile` reads the clip (torchaudio's loader requires
   TorchCodec, which is unavailable on Windows; `soundfile` is more robust).
2. **Slice** — `chunking.slice_waveform()` cuts a mono window
   `[offset_s, offset_s + 3.0)`, clamped to the clip's end.
3. **Classify** — `classifier.classify()` runs the extractor + model
   (`torch.no_grad()`), softmaxes the logits, takes `p_synth`.
4. **Decide** — `is_synthetic = p_synth >= DECISION_THRESHOLD` (0.30, calibrated
   — see §5). `confidence = max(p_synth, 1 - p_synth)`.
5. **Observe** — `prism.emit_trace()` logs one trace per chunk (fire-and-forget)
   with ground truth, generator type, chunk length, run version, and the
   decision threshold that produced the verdict.

**Latency: ~150–700 ms per 3 s chunk on CPU** — comfortably inside the 3 s
demo cadence. GPU is not required for inference; it only matters for
fine-tuning.

### 2.3 Why chunked inference (not whole-clip)

A scam call must be flagged *while it is happening*. Chunking gives per-window
verdicts that (a) update the live confidence bar in the UI, (b) let a verdict
form within the first ~6–9 seconds of a call, and (c) each become an
independent PRISM trace — which is what makes failure diagnosis possible.

## 3. Why it works (and where it doesn't)

### 3.1 Evidence from the held-out evaluation

Held-out set: **193 real ASVspoof 2019 LA eval clips** (50 human speakers +
143 synthesized, 13 attack types A07–A19), sliced into **204 chunks**,
replayed through the live API with ground truth attached.

| Run | Accuracy | A10 | Worst others | Human |
|---|---|---|---|---|
| v1 (threshold 0.50) | 96.6% (197/204) | **54.5%** | A13 91.7%, A18 90.9% | 100% |
| v2 (threshold 0.30) | **97.5% (199/204)** | **72.7%** | unchanged | 100% |

### 3.2 Why the threshold change helped (the confidence analysis)

`ml/analyze_confidence.py` recovered the raw `p_synth` for every chunk of the
weak groups. Findings (`ml/threshold_sweep.json`):

```
attack_A10   n=11  mean p_synth=0.627  min=0.002  max=0.997   ← bimodal
attack_A13   n=12  mean=0.906  min=0.098
attack_A18   n=11  mean=0.909  min=0.010
human        n=51  mean=0.005  max=0.153                  ← wide safety gap
```

- A10's misses are **borderline cases** (two chunks at p_synth 0.402 and 0.498),
  not hard failures. Humans never exceed **0.153**. A threshold of 0.30 flips
  exactly the 2 borderline A10 chunks and **zero** humans — a provably safe
  move on this data (0.147 margin below the lowest human false-positive
  risk).
- The remaining A10/A13/A18 misses have p_synth < 0.10 — the model is
  *confidently wrong* on those. No threshold can fix them; that is a
  representation problem, which is what fine-tuning is for (§6).

### 3.3 Honest limits

- ASVspoof 2019 attacks are 2019-era; modern neural vocoders may differ.
- The held-out set is small at the per-attack level (11–13 chunks each);
  percentages there are coarse.
- The model is speech-specific: pure tones (the old synthetic test clips)
  score only ~0.7 p_synth — non-speech audio is out of distribution.
- No noise/channel robustness has been tested (reverb, codecs, phone
  compression).

## 4. How the AI connects to the project

```
React call screen ──POST /classify-chunk──▶ FastAPI backend
        ▲                                        │
        │ verdict + confidence        sf.read → chunking.slice_waveform
        │                                        │
        └──── live confidence bar ◀── classifier.classify (wav2vec2)
                                                 │
                                                 ▼
                                       prism.emit_trace() ──▶ PRISM cloud
                                       (ground_truth, generator_type,
                                        run_version, decision_threshold)
```

- **Frontend** renders the verdicts live (confidence bar, trend chart) — the AI
  is the product's core interaction.
- **PRISM** receives one trace per chunk, tagged with ground truth and
  `run_version`. That is what turned "the model is 96.6%" into "attack A10 is
  at 54.5% while everything else is ≥91%" — the diagnosis that drove the v2
  fix.
- **ML scripts** (`ml/`) exist solely to feed and measure the model:
  `download_asvspoof.py` → `prepare_data.py` (real clips) → `replay_batch.py`
  (v1/v2 scoring) → `analyze_confidence.py` (parameter calibration) →
  `finetune.py` (optional, §6).

### What the AI contributes to VoxG's purpose

VoxG's pitch: **stop AI-voice scam calls before the human is deceived.** The
classifier is the only component that can do that — everything else (call UI,
trace pipeline, dashboards) exists to deliver its verdicts transparently and to
improve them systematically. Its 97.5% per-chunk accuracy with a live
sub-second verdict is the demonstrable core of the hackathon demo.

## 5. Parameter changes (what changed, why, and how to change it back)

| Parameter | Before | After | Where | Why |
|---|---|---|---|---|
| `DECISION_THRESHOLD` | 0.50 (implicit) | **0.30** | `backend/app/config.py` (`VOXG_DECISION_THRESHOLD` env) | A10 borderline chunks at p_synth 0.40–0.50; humans max 0.153 → flipping them is safe and free (+2 chunks, +0.9 pp overall) |
| `decision_threshold` in trace metadata | — | added | `backend/app/main.py` | Every PRISM trace now records the boundary that produced it — v1/v2 comparisons on the dashboard show *what changed*, not just *that something changed* |
| `MODEL_ID` | `Sara1708/...` (incomplete on Hub) | `Bisher/wav2vec2_ASV_deepfake_audio_detection` | `backend/app/config.py` (`VOXG_MODEL_ID` env) | Original checkpoint lacked feature-extractor config → random head; audited 4 alternatives, chose the verified-complete base-size one (fastest CPU) |
| Audio loading | `torchaudio.load` | `soundfile` | `backend/app/main.py` | torchaudio requires TorchCodec on Windows (unavailable) |
| Held-out clip resolution | — | `ml/data/heldout/` via `HELDOUT_AUDIO_DIR` | `backend/app/config.py`, `main.py` | `prepare_data.py` originally never wrote held-out audio → replay would 404; fixed in the data pipeline |

The threshold sweep is reproducible: `python ml/analyze_confidence.py`
(requires `ml/data/heldout/` + manifest from `prepare_data.py`), and its output
lives in `ml/threshold_sweep.json`. Roll back anytime with
`VOXG_DECISION_THRESHOLD=0.50`.

## 6. Does the model need fine-tuning? (verdict: no)

**Recommendation: no fine-tuning before the hackathon.** Three reasons:

1. **The numbers don't demand it.** 97.5% with humans at 100% (zero false
   alarms on real people — the commercially critical metric for a scam
   *screening* product). The residual errors are 5 chunks across 3 attack
   types.
2. **The residual errors are out-of-representation, not marginal.** Missed
   chunks sit at p_synth < 0.10 — head fine-tuning on 143 synthetic clips
   (CPU, time-boxed) is unlikely to move them and risks degrading the 100%
   human rate via overfitting.
3. **Operational cost/risk.** CPU-only torch (the CUDA wheel could not be
   installed on this machine); a fine-tune would take hours and introduce a
   new checkpoint swap right before the demo.

**When fine-tuning WOULD be right (post-hackathon roadmap):** collect real
vocoder/diversity data (post-2019 generators), fine-tune the wav2vec2 feature
extractor (not just the head) on a GPU with the full ASVspoof training split,
and add noise/channel augmentation. The scaffolding for that exists in
`ml/finetune.py` (time-boxed, wall-clock budget) — it is deliberately not on
the critical path.

## 7. File map (AI component)

| File | Role |
|---|---|
| `backend/app/classifier.py` | Model load (with checkpoint fallback) + `classify()` → `(is_synthetic, confidence)` |
| `backend/app/chunking.py` | Waveform slicing into 2–4 s mono windows |
| `backend/app/config.py` | `MODEL_ID`, `DECISION_THRESHOLD`, paths — all env-overridable |
| `backend/app/main.py` | `/classify-chunk`: load → slice → classify → PRISM trace |
| `backend/app/prism.py` | Fire-and-forget trace emission (never blocks a verdict) |
| `ml/download_asvspoof.py` | Resumable parquet downloader → `D:\VoxGData\asvspoof\` |
| `ml/prepare_data.py` | Demo clips (16) + held-out set (193) from the official protocol |
| `ml/replay_batch.py` | v1/v2 scoring runs through the live API; writes `ml/results_*.json` |
| `ml/analyze_confidence.py` | Threshold-sweep calibration; writes `ml/threshold_sweep.json` |
| `ml/zero_shot_eval.py` | Offline baseline scorer (cross-check for replay numbers) |
| `ml/finetune.py` | Time-boxed head fine-tune (optional, not on the critical path) |
